# 施工进度计划生成终端（terminal/）

零第三方依赖（仅 Python 标准库）的终端创作端。配合后端侧自研流水线（`../backend/`）使用，
两端经**统一 SSE 事件契约**会师。事件的唯一真源是
`../backend/pipeline/events.py`（9 类事件常量），数据契约的唯一真源是
`../backend/pipeline/schemas.py`。主链节点顺序与界面名的唯一真源是
`../backend/pipeline/builder.py` 的 `_main_nodes()` / `PIPELINE_TITLES`（**27 个节点**）。

> 日常**不需要**单独起终端：双击仓库根目录的 `一键测试.bat` 即可（它装依赖 → 引导密钥 → 起后端 → 起终端 → 退出时收尾）。下面是手动起法。

## 快速开始

### 真实后端（需启动 backend/）

```bat
:: 窗口 A：启动自研后端
cd ..\backend
pip install -r requirements.txt
python -m uvicorn main:app --port 8000

:: 窗口 B：启动终端（连接真实后端）
python console.py --real
```

先输入 `/mode plan` 进入**生成计划**模式，再描述项目，即可看到"思考→行动→观察"的流式过程（配色只有 4 类语义色 + 灰：
青=标题/状态、绿=成功、黄=待确认/警告、红=失败，另加暗灰说明）：

- `▶ 节点启动`（青）→ 折叠进度行（灰，长节点每 2 秒最多一条）→ `✔ 节点完成`（绿）
- 遇到人工门时打印**门的正文 + 输入提示**（如 `❓ 检测到计划请求…[Y/n，回车=取消]`）
- 收尾（尚未审计）：`📄 计划数据已生成并落盘（尚未审计）`，计划 JSON 落盘 `backend/plans/plan_*.json`，
  **定稿 Word 与看板要等三轮回审门都通过后才产出**
- 开场白只有一行品牌字「海之子 · 建策 BuildPlan」（用户明确要求简洁；`branding.py` 的
  `welcome_lines()` 与 `test_开场白只留一行品牌` 守着这件事）

## 模式（用户手选，第 34 轮：取消意图识别）

输入框左侧**固定显示当前模式**，用户随时知道自己处在哪：
`[normal] 你 ▸`、`[plan] 你 ▸`、`[revise · plan_xxx] 你 ▸`、`[import] 你 ▸`。

| 模式 | 怎么进 | 裸输入被当作 | 怎么出 |
|---|---|---|---|
| **normal 普通** | 启动即是；`/mode normal` 或 `/exit` 可回来（默认） | **纯聊天**：只回答，**绝不开流水线**；说了要生成计划 → 只提示 `/mode plan` | — |
| **plan 生成计划** | 手选 `/mode plan` | 一律按"要生成计划"走（描述项目即开始编制，先过工作模式确认门） | `/exit` |
| **revise 修改计划** | 手选 `/mode revise`（未选基准计划时给菜单） | **先看后改**：默认当聊天（可基于当前计划回答），识别到修改意图才给预览、问 `y` | `/exit` |
| **import 导入计划** | 手选 `/mode import`，或修改模式里选 `[2]`、`/import <路径>` | 给的计划 JSON 路径 | `/exit` |

- **意图识别已取消**：不再有"自动切模式"——普通模式只回答，`/mode plan` 是唯一的手动入口；
- 进入修改模式时会固定显示**基准计划编号**；
- 模式与计划编号**落盘**（`POST /mode`）：关掉终端再打开，还在改同一份计划；
  测试可用 `BUILDPLAN_MODE_FILE` 把这个文件指到临时路径，避免用例串台；
- **模式内提到别的模式的事 → 只提示怎么切，不自动切**（例如普通模式里说"帮我改一下计划"，会得到「这属于【修改计划】模式…请输入 `/mode revise`」）；
- 修改模式里**裸输入默认当聊天**（可基于当前计划回答）：只有命中确定性修改关键词（不调模型）才先调后端 `dry_run` 拿预览，打出"我打算改这些…"并问「确认要改吗？输入 y 执行」——**确认后才真改**，回车/其他输入一律不改（计划纹丝不动）；
- 斜杠命令**在任何模式都能用**，模式只决定"裸输入"怎么解释；
- 从没选过基准计划时，修改模式给 `[1] 改已有的 / [2] 导入 / [3] 先生成再改 / [0] 返回`。

## 命令

> 全部斜杠命令**只在"没在跑流水线"时可用**；流水线运行中主线程在读 SSE，键盘输入无效
> （`Ctrl+C` 可中断）。流水线停在人工门时，输入的是**门的答案**（`Y`/编号/文本/`/abort`），
> 不是命令 —— 但三道门（文件门 / 参数门 / 审计门）都认 `/abort`，会**真的中止**。

> **先切模式、再说话**：`/mode plan` 或 `/mode revise` 之后，裸输入才有模式含义。

| 命令 | 说明 |
|---|---|
| `/help` | 帮助（开场白里也会讲一遍"四种模式"） |
| `/mode normal` | 普通：纯聊天（默认；不做意图识别，不会自动开流水线） |
| `/mode plan` | 生成计划：描述项目即开始编制 |
| `/mode revise` | 修改计划：先选一份计划，再问它 / 改它（改前先给预览，确认 `y` 才改） |
| `/mode import` | 导入计划：给一个计划 JSON 的路径 |
| `/exit`（别名 `/quit-mode`、裸输入 `退出模式`） | 回普通模式（**不退出程序**） |
| `/show` | 浏览器打开当前计划看板（单文件 HTML） |
| **`/plans`** | 列出本机已有的计划（第二次打开也能接着改） |
| **`/open [计划编号]`** | 打开一份已有计划（不带参数 = 最新一份）→ 进入修改模式 |
| **`/import <文件>`** | 从一份计划 JSON 导入（过契约校验 → 建档案 → 可修改） |
| **`/wbs`** | 列出已留档的 WBS 树（哪棵树来自哪次输入） |
| **`/inputs`** | 列出已留档的输入（编号 / 文本或文件路径） |
| `/revise <一句话>` | **改计划**：一句话 → 规范指令 → 真重排 → 报新旧总工期 |
| `/versions` | 修订链：改过几版、每版改了什么 |
| `/undo` | 回退一轮修改 |
| `/goto <版本号>` | 回到指定版本（`/goto 0` = 初版） |
| `/sources [id/关键词]` | 逐值溯源：每个数字从哪来 |
| `/cost` | 本次运行的 token 用量与费用 |
| `/confirm` | 确认当前计划 |
| `/history` | 查看对话历史 |
| `/status` | 查看后端与运行状态 |
| `/switch` | 切换后端：云端主后端 ↔ 本地 llama.cpp |
| **`/llm`** | 看当前模型档位 + 列出已保存的多套 key（key 打码） |
| **`/llm-use <编号或名字>`** | **热切换**模型档位，下一条消息即生效（不用重启、不用重跑） |
| **`/llm-add`** | 新增一套 key / 端点（引导式问答，key 只写本机） |
| **`/llm-del <编号>`** | 删除某个档位（不影响已生成的计划） |
| `/verbose` | 切换详细模式（默认折叠逐节点进度；打开后全量打印） |
| `/quit` | 退出（流水线运行中会先询问是否取消） |
| `/continue` `/retry` `/edit` `/abort` `/cancel` | 迭代命令。⚠️ **当前主链没有节点声明暂停点**（`pause_point`），前三个在主链上走不到；`/abort`、`/cancel` 正常可用（文件门 / 参数门 / 审计门都认） |
| `!命令` | 透传系统命令 |

## 双轨降级说明

- **云端主后端**：`http://localhost:8000`（FastAPI，质量优先）。
- **本地 llama.cpp**：`http://127.0.0.1:8080`（可选，数据本地化/离线降级）。
- `/switch` 在两者间切换。**注意：本地后端必须实现与云端后端相同的数据契约**
  （`POST /chat` 的 SSE 事件流 + `/confirm` + `/resume` + `/cancel`），否则切换无意义——
  它不能是一个裸的 OpenAI 聊天接口。
