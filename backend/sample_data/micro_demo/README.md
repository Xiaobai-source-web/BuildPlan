# 微型标本：粗粒度 vs 细粒度计划对比

## 项目概况

两个标本描述**同一个 3 层办公楼项目**（2026-03-01 开工），**工程量完全相同**，
仅展示粒度不同：

| | 标本 A | 标本 B |
|---|---|---|
| 粒度 | 工序级 × 按层（细） | 工种级 × 整栋（粗） |
| 面向对象 | 项目部 / 现场施工员 | 管理层 / 公司领导 |
| 展示行数（叶子数） | 20 | 11 |
| 总工期 | **45 天** | **49 天** |
| 关键路径节点数 | 18 | 11 |

> 以上数字 2026-09-21 复核实测一致（叶子数逐节点数、总工期按关键路径工期求和与
> CPM 前向遍历两条口径各算一遍）。
>
> **两个总工期不同是真实的粒度效应，不是笔误。**
> 粗粒度把同一工种的多层作业合并成一行后，主体结构只能整栋串行：
> 钢筋 9 + 模板 7 + 混凝土 3 + 砌体 6 = 25 天；细粒度允许逐层搭接，主体段更短。
>
> **对生产的含义**：上卷展示时**必须传真实排程**取时间跨度
> （`group_rows(wbs, depth, grouping, schedule=...)`，实际签名见
> `backend/pipeline/quantity.py:341`），**绝不能在上卷时重算工期**——
> 否则同一份计划的粗/细视图会给出两个互相矛盾的总工期。

## 标本 A：工序级 × 按层（细粒度）

- **粒度参数**：`DEPTH_COMPONENT`（工序级，`backend/pipeline/quantity.py:256`）+ `FLOOR_PER_FLOOR`（按层，`:259`）
- **叶子节点数**：20，总工期 45 天，关键路径 18 节点（2026-09-21 复核实测一致）
- **特点**：每层楼的每道工序（钢筋绑扎、模板安装、混凝土浇筑、砌体）单独成行，
  精确到楼层区间（如"Ⅰ区 1-1层 钢筋绑扎"），方便现场逐日跟踪。

## 标本 B：工种级 × 整栋（粗粒度）

- **粒度参数**：`DEPTH_COARSE`（工种级，`backend/pipeline/quantity.py:255`）+ `FLOOR_WHOLE`（整栋，`:261`）
- **叶子节点数**：11，总工期 49 天，关键路径 11 节点（2026-09-21 复核实测一致）
- **特点**：同一工种的多层工程量合并为一行（如"Ⅰ区 1-3层 钢筋绑扎（汇总）"），
  一眼看清各工种的总工作量和总工期，适合高层决策与资源统筹。

> 粒度常量全表（`backend/pipeline/quantity.py:255-265`）：
> `DEPTHS = (DEPTH_COMPONENT, DEPTH_COARSE)`、
> `FLOOR_GROUPINGS = (FLOOR_PER_FLOOR, FLOOR_PER_5, FLOOR_WHOLE)`
> —— 两标本只用到其中的 `DEPTH_COMPONENT + FLOOR_PER_FLOOR` 与 `DEPTH_COARSE + FLOOR_WHOLE`。

## 行数对比

| 维度 | 标本 A（细） | 标本 B（粗） | 倍数 |
|------|-------------|-------------|------|
| 展示行数 | 20 | 11 | ≈ 1.8× |

## 上卷关系

标本 B 是标本 A 的**严格上卷**，且已在**工程量与单位层面**逐行核对通过
（不只是行数相等）：

- 对 A 的 WBS 调用 `group_rows(wbs, depth=DEPTH_COARSE, grouping=FLOOR_WHOLE)` 得到 **11 行**，
  键集与 B 的 11 行**完全相同**；
- 11/11 行的**工程量与单位逐一相等**（如 `3.1 钢筋工程`：A 上卷 35.5 t = B 的 35.5 t）。

两者不是各写各的，而是同一份数据在不同粒度下的投影。

## 阶段划分

| 阶段 | A 的行数 | B 的行数 |
|------|---------|---------|
| 施工准备 | 1 | 1 |
| 地基与基础 | 3 | 2 |
| 主体结构（3层 × 4工序） | 12 | 4 |
| 二次结构与砌体 | 1 | 1 |
| 装饰装修 | 3 | 3 |
| **合计** | **20** | **11** |

## 维护约定

派生值（总工期、关键路径、材料汇总）**必须由数据算出，不能手写**。
`backend/tests/test_micro_specimens.py` 的 `TestDerivedValuesConsistent` 会
独立实现一遍 CPM 前向遍历并逐项重算，锁死以下 **6 条不变量**
（该类共 6 个测试方法；2026-09-21 实测 `python -m pytest tests/test_micro_specimens.py -q`
→ **16 passed**）：

| 不变量 | 说明 |
|--------|------|
| 关键路径工期之和 == 总工期 | 防止关键路径"抄近路"跳过更长的并行支线 |
| CPM 前向遍历 == 总工期 | 防止总工期与依赖关系脱节 |
| 逐节点 ES == 关键路径累加 | 防止标出的路径其实不是最长路 |
| `overview.total_duration_days` == `cpm_result.total_duration_days` | 防两个字段各写各的 |
| `material_summary` == 叶子实算 | 防止汇总表少算 |
| 无悬挂依赖引用 | 防止引用了不存在的任务 |

> **注意**：`resource_plan` 中的 `total_manpower_days` / `peak_manpower` 为
> **示意值**，不可由文件内数据推导（缺少班组配员），请勿当作排程结果引用。
