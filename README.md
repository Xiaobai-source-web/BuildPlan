## 这是什么（30 秒）

**一句话 → 一份可审计的施工进度计划。**

你在终端里先输入 `/mode plan` 进入**生成计划**模式，再写一句项目描述（或给一份施工组织设计的文件路径），系统自动完成
**读取项目参数 → 编制 WBS 分工 → 匹配消耗量定额 → 编排工序先后 → 排程与两版工期 → 算资源与工日 → 组装计划数据 → 生成监督报告**，
最后交付两份东西：

- **`施工进度计划.docx`** —— 含总览、**数据来源与置信度**、工序表（**排程跨度与 WBS 目标分列**）、关键里程碑、横道图、**施工组织口径与组织缺口**、人力/设备荷载、**节点级告警**、**模型用量与费用**、监督报告
- **`计划看板.html`** —— 自包含网页（甘特图、人力曲线、设备荷载、**置信度卡片**、审计戳），双击即开

适合：**施工管理人员、进度计划编制人员、项目经理**——不需要会编程，也不需要装 MS Project / P6。

## 为什么和别的工具不一样（三条硬承诺）

| 承诺 | 具体含义 |
|---|---|
| **定额为据** | 定额是**唯一**产能真源：`工日需求 = 工程量 ÷ 定额产能`（不可压缩），`工期 = 工日需求 ÷ 设计班组人数`。**绝不为凑工期改定额**，这条有回归测试守着。 |
| **算两版，不迎合** | 同时给出**理论最短**与**资源不超额**两版。给了标准层节拍时，走**施工组织层**：`工期 = 工日 ÷ (作业面数 × 每面人数 × 班次 × 效率折减)`，四道闸（每面上限 / 作业面上限 / 班次 / η）卡住"堆人赶工"；做不到就出**组织缺口报告**逐条说明缺口与可动杠杆，不虚报。**你提的目标工期只作参照**，系统不迁就。 |
| **审得了** | 三道**回审门**（WBS 结构 / 两版工期 / Word 草案）由你拍板：输入 `Y` 通过；输入文字即审计意见——计划保持「**未审计**」，且**不出定稿与看板**（不装作通过）。**定稿里印不印「已审计」，只取决于计划数据里真的记了什么**：轮次不全、缺记录、或某一轮是系统代答，交付物就如实印「未审计」并说明原因。`/sources` 可逐值追溯每个数字的来源。 |

另外三条：

- **AI 补的东西全部标明，且不当你的限额**：模型补的参数、边界条件、设备与劳动力清单，一律标注「模型估算，非用户输入」，**不作为你的限额使用**（不会拿它顶掉算出来的数）。
- **定额与工作面容量的 AI 数据都参与计算，但全部逐条标明（2026-09-20 起）**：工作面容量改由**资源工作面指标 MWI**（`Resource_Workface_Index`）与叶子自带标定值给出，照常参与计算与封顶，取不到时按物理兜底上限并由警告逐条报出（知识库里的 `Workface_Capacity_Rule` 表已在域 1.6 删除）。**定额同理**：AI 凭经验编的定额（`confidence=estimated`、绑定来源 `AI_ESTIMATE_V1`、`match_type=ai`）**照常决定工序工期与班组人数**，因为它目前是装饰 / 机电 / 施工准备这类工序**唯一可得的**覆盖面来源；此前一律不采用，会让约 24% 的工序在人工曲线里等于不存在（峰值人数只是下限）。放开后曲线完整，但**数字里含 AI 成分**：Word 与看板在逐条工序的「依据 / 资源」列写明「**AI 经验估算定额（无规范依据，待审）**」，并在「数据来源与置信度」章节给出条数（状态名 `released_ai`）；**导入真实规范后应逐条清退**（`AI_ESTIMATE_V1` 的自述保留）。**仍然拦住的只有四类**：① 人工**否决**（`review_state == "rejected"`，唯一的硬开关）；② **单位不可换算**（如任务 m² 对定额分母 m³ 且缺厚度参数）；③ **定额口径与任务不符**（method conflict）；④ **定额值为空**。这四类任务仍然没有班组、**工期沿用 WBS 估算**，交付物如实写「工期沿用 WBS 估算，未计算班组」。
- **改得动**：进入**修改计划**模式（`/mode revise`）后，先选一份计划，再用一句自然语言改它（如"把主体结构钢筋工加到 60 人"）——**改前会先给你看"我打算改这些"，输入 `y` 确认才真改**；只重算受影响的下游，改动全程留痕（`/versions` `/undo` `/goto`）。
- **本地单机**：全部在本机跑，密钥只存 `backend\.env`，不外传。**没有密钥也能端到端出结果**（自动走确定性兜底）——这种情况下交付物顶部会打上「**模型未参与**」标示，并说明参数/边界条件可能缺失，**别拿它当方案用**。

## 30 秒跑起来

```powershell
# 1) 双击（或命令行运行）
一键测试.bat

# 2) 首次会让你选一家大模型厂商并粘贴密钥（只写进本机 backend\.env）
#    接口是标准 OpenAI 兼容协议 —— 通义千问 / DeepSeek / Kimi / 智谱 / 硅基流动 /
#    OpenAI / 本地 Ollama 都能用；菜单里也能选「不填密钥，用确定性兜底跑」

# 3) 先输入 /mode plan 进入「生成计划」模式（输入框左侧会显示 [plan]），
#    再输入一句项目描述（**结构形式**与**基础类型**必须写，见下方注意）：
1 栋 3 层框架结构办公楼，总建筑面积 1500 ㎡，1 层地下室，独立基础，混凝土约 1200 m³，钢筋约 90 吨，开工 2026-03-01
```

> **注意**：系统会要求 **层数 / 总建筑面积 / 结构形式 / 基础类型** 四项
> （真源：`backend/pipeline/nodes/boundary.py` 的 `REQUIRED_KEYS`）——它们直接决定工程量口径。
> 缺了会在"参数复核门"提示你补齐；只想先用默认值试算时，**必须明确输入「试算」**——
> 试算结果会在交付物上标注"**不可用于施工**"。
>
> 其中**「结构形式」与「基础类型」是绝对必要项（`ABSOLUTE_KEYS`）：连「试算」也不放行**，
> 提取不到就中断、绝不出计划——因为整份计划的工程量口径都建立在这两项之上。
> **栋数不在必要项里**：不写就按"单栋"编制并在交付物上标注（多栋项目请写明"12 栋"）。

详细操作见 **[`建策BuildPlan_运行指南.md`](建策BuildPlan_运行指南.md)**。

> 终端是**顺序输出**（不占屏、不做屏幕定位）：**鼠标滚轮翻历史、拖选复制文字都是终端原生的**。
> （想试底部固定输入框：`set BUILDPLAN_TUI=1`，代价是滚轮与拖选会失效，见运行指南 FAQ。）

### 「审得了」的两个侧面

**范围内的算清楚。** 目标工期只作参照：系统按定额算出工日需求，再把你的目标工期并排列出来；
装不下就逐条报缺口，**不改定额去凑目标**。

**范围外的明说不做。** `项目样例\示例4_真实工程用例_广州潭村安置地块.docx`
是一份真实工程的施工组织关键参数，里面含 **装配式建筑**（阳台板 / 凸窗 / 叠合板 / 楼梯 +
灌浆连接）。**本系统不支持装配式建筑**——构件拆分、节点连接、吊装与灌浆工序不在编制范围内。
喂进去它会**明确拒绝并说明原因，不生成计划**，而不是编一份看起来像的方案给你。

详见 [`项目样例/说明.md`](项目样例/说明.md) 与《建策BuildPlan_技术说明文档_v3.0.docx》第 1.3 节。

## 已知局限（如实说明，不粉饰）

| 局限 | 现状与影响 |
|---|---|
| **定额覆盖率不是 100%** | **没有任何可用定额**的工序（单位不可换算 / 定额口径与任务不符 / 定额值为空 / 你人工否决过），其工期**沿用 WBS 估算**、**未计算班组**并在交付物上一一标注（实测：6 栋算例 84.3%、12 栋算例 88.1% 有据可查，另有一批 AI 经验估算定额按 `released_ai` 计入覆盖率并逐条标注）。系统不会在排程时为凑数编一个定额。 |
| **口径是"标准栋"** | 多栋项目按标准栋编制、各栋平行施工；你给的全场资源限额会按栋数分摊成单栋限额，交付物上写明。 |
| **机械主导任务的人工需求单列** | 现浇混凝土这类由知识库标为"机械主导"的活动，工期走台班定额；其人工需求单独报出，本版不用它延长工期。 |
| **定额子目匹配可能出错** | 出现"任务描述像机械作业、却绑到人工定额"这类张冠李戴时，系统会检测冲突、尝试在同工种内改绑为机械活动，并在警告里说明。 |
| **大模型输出有波动** | 读懂需求、拆解工序、审核合理性这几步由模型负责（其余全部由代码计算）。同一句话两次运行，工期与资源数字**确定不变**，工序命名可能略有差异。 |

## 技术要点（给想深入的人）

- **27 节点顺序流水线**：`router → work_confirm → doc_load → extractor → param_review → boundary → kb_scope → wbs_agent → beat_build → plan_level → audit_wbs → quantity_fill → norm_bind → crew_bind → deps → cpm → scheduler → audit_schedule → resource → assembler → reporter → confirm → deliver → word_draft → audit_draft → word_export → html_page`
  （上面是**代码里的节点名**；终端界面上显示的是更口语化的**界面名**，两套名字的对照真源是 `backend/pipeline/builder.py` 的 `PIPELINE_TITLES` 与 `_main_nodes()`。例：`router`＝识别当前模式、`extractor`＝读取项目参数、`kb_scope`＝范围与结构映射、`wbs_agent`＝编制 WBS 分工、`beat_build`＝节拍流水分段、`plan_level`＝选择展示细度、`quantity_fill`＝补全各工序工程量、`norm_bind`＝匹配消耗量定额、`crew_bind`＝配机械与班组、`deps`＝编排工序先后、`cpm`＝计算关键路径、`scheduler`＝排程与两版工期、`resource`＝算资源与工日、`assembler`＝组装计划数据、`word_draft`＝导出 Word 草案（未审计）、`word_export`＝导出 Word 文档、`html_page`＝导出可视化看板）
- **确定性优先**：CPM、两版排程、资源定额、汇总、图表全部由代码计算，可复现、可复算；大模型只负责"读懂需求、拆解工序、审核合理性"。
- **不依赖外部 Agent 框架**：自研 Pipeline 引擎，主链 27 节点顺序执行，**每个节点执行前存档检查点**；支持人工门（确认 / 参数复核 / 三轮回审 / WBS 复评）、暂停与取消。
- **质量保障**：**3002 条自动化测试**（`cd backend && python -m pytest -q`），含"绝不为凑工期改定额""任务工期与日期单一真源""班组单一真源""算式末值 == 工程量""审计门的证据必须覆盖全部阶段""**交付物不许印数据里没有的东西**""关键路径任务数与长度分列""**有来路的工序不许成为孤儿（缺依赖必告警）**""单层量物理不可能必标记"等硬不变量。
