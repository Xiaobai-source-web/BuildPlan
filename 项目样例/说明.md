# 示例输入（可直接拿来试）

这里的文件都是**可以原样喂给系统**的输入。在终端里先输入 `/mode plan` 进入生成计划模式，
再给出描述或文件的完整路径即可，例如：

```
请按这个资料做计划：D:\...\项目样例\示例1_办公楼.txt
```

| 文件 | 是什么 | 拿来试什么 |
|---|---|---|
| `示例1_办公楼.txt` | 一句话/清单式项目描述（12 层办公楼，8500 ㎡） | 最快跑通全流程 |
| `示例2_仓库.txt` | 单层大体量厂房（门式刚架钢结构，12000 ㎡） | 看单层、大面积的量级处理 |
| `示例3_住宅楼.txt` | 高层住宅（18 层，剪力墙，PHC 管桩，14200 ㎡） | 看标准层流水（节拍）展开 |
| `示例3_住宅楼_对比版.txt` | 同量级的另一份描述（18 层、地下 2 层、15000 ㎡） | **「四系统同题对比」用的就是这一份**（见《技术说明文档》§12.3） |
| `测试算例_LLM对比.txt` | 住宅小区（6 栋 / 地上 11 层 / 地下 1 层 / 剪力墙 / 筏板基础 / 4.2 万 ㎡） | **推荐用它演示**：不带密钥也能跑、结果可复现 |

## ★ 先读这一条：四项必要参数

系统要求四项参数（真源 `backend/pipeline/nodes/boundary.py` 的 `REQUIRED_KEYS`）：

| 参数 | 缺了会怎样 |
|---|---|
| **层数**、**总建筑面积** | 参数门提示补齐；明确输入「试算」可用默认值先算一版（结果标「不可用于施工」） |
| **结构形式**、**基础类型** | **绝对必要项**（`ABSOLUTE_KEYS`）——**连「试算」也不放行**，提取不到就中断 |

**栋数不在这四项里**：不写就按「单栋」编制并在交付物上标注（多栋项目请写明「12 栋」）。

> 无密钥的确定性兜底路径**读不出自由文本里的结构/基础描述**（它靠正则+规则，不靠模型）。
> 所以 `示例3_住宅楼.txt` 在无密钥时会被参数门拦下——在参数门补一句
> `结构形式：剪力墙结构，基础类型：预应力管桩` 即可（或明确输入「试算」）。
> 有模型密钥时这一步通常自动提取成功。

## 可复现的实测结果（确定性兜底 · 不联网 · 不调模型）

**算例 · 6 栋 / 11 层 / 4.2 万 ㎡ 住宅小区**（输入即 `测试算例_LLM对比.txt`）：

| 指标 | 结果 |
|---|---|
| 工序叶子 / 关键路径任务 | **127 条 / 51 条** |
| 总工期 | **180 天**（2026-03-01 → 2026-08-27） |
| 定额口径覆盖率 | **84.3%**（107/127） |
| 人工峰值 / 总人工日 | **209 人 / 20,430 人日** |
| 数据来源可信度 | 知识库 40% / AI 60%（逐条标注） |

**算例 · 12 栋 / 38 层 / 21.5 万 ㎡ 住宅安置地块**（内置场景，一条命令复现）：

```powershell
python devtools\measure_plan.py --only "自由编制"     # 约 15 秒
```

| 指标 | 结果 |
|---|---|
| 工序叶子 / 关键路径任务 | **377 条 / 51 条** |
| 两版工期（无人力限额） | 理论最短 = 资源不超额 = **391 天** |
| 定额口径覆盖率 | **88.1%**（332/377） |
| 定额工日需求 | **30,682 人日**（另有机械主导 552 人日，实际总用工 31,234 人日） |
| 人工峰值 / 总人工日 | **235 人 / 34,639 人日** |

> 同一输入重跑数字不变。第 37–42 轮与 2026-09-20 改过几处口径
> （地下室兜底工程量、施工组织层、工作面容量上限重定、AI 经验估算定额改为参与计算并逐条标注），
> **换一份输入数字自然不同——以你实际运行的结果为准**。

## 关于示例 4（真实算例，「审得了」的另一面）

这份文档给的是**项目级**参数（总建筑面积 301,354.26 ㎡、总工期 900 日历天、总劳动力峰值 929 人等），
其「特殊工艺」一栏写明含 **装配式建筑施工**（阳台板、凸窗、叠合板、楼梯）与装配式构件灌浆养护。

**本系统不支持装配式建筑。** 装配式是一套完整的建筑体系——构件拆分、节点连接、吊装与灌浆工序
都不在本系统的编制范围内。所以把这份文档喂进去，系统会**明确拒绝并说明原因、不生成计划**，
而不会编一份看起来像的方案。

这正是「审得了」的另一面：**范围内的算清楚，范围外的明说不做**。
想试真实规模的多栋算例，用上面的 `measure_plan.py` 内置场景，或自己写一句
`12 栋，地上 38 层，结构形式：框架-剪力墙结构，基础类型：筏板基础，总建筑面积 215000 ㎡` 的现浇项目描述。

> 完整叙述见《建策BuildPlan_技术说明文档_v3.0.docx》第 1.3 节。
